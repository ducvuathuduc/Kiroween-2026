# Backlog #4 — In-Browser Semantic Search

Owner-approved scope: `@huggingface/transformers` (`4.3.2`) running client-side inside a dedicated Web Worker (`src/workers/embed.worker.ts`) using quantized `all-MiniLM-L6-v2` (`dtype: 'q8'`, 384 dimensions, ~23 MB). Do NOT use Voy or Pagefind, and never import `@huggingface/transformers` in `server.ts` or `server/*`.

## Requirements (EARS)

1. **Lazy Model Initialization**: When the application loads initially, the system SHALL NOT download model weights or spawn the embedding Web Worker; it SHALL initialize `src/workers/embed.worker.ts` and load `Xenova/all-MiniLM-L6-v2` (`dtype: 'q8'`, mean pooling, L2 normalized) only upon the user's first semantic search query while semantic search is enabled.
2. **Browser Model Caching & Offline Search**: When the local embedding model downloads, the system SHALL enable `@huggingface/transformers` browser caching (`env.useBrowserCache = true`, Cache Storage `'transformers-cache'`), SHALL persist computed 384-dimensional item vectors (`{ itemId, vec, model }`) in IndexedDB (`src/lib/storage.ts`), and SHALL execute repeat semantic searches offline using cached weights and vectors without network calls.
3. **Hybrid Scoring Without Modifying 4D Signal Score**: When ranking items for a query in semantic mode, `src/lib/semanticSearch.ts` SHALL compute cosine similarity against cached/worker embeddings and combine scores using `0.6 * semantic + 0.4 * keyword` (`fuzzyMatchScore` normalized to `[0, 1]`), surfacing non-keyword semantic matches (`similarity >= 0.25`) while keeping deterministic `scoreItem()` / `explainScore()` 4D signal scores completely unchanged and never labeled "AI".
4. **Progress & Match Affordances**: While the model is downloading on first search, `src/components/ItemList.tsx` (and `CommandPalette.tsx` when open) SHALL announce download progress inline via a polite status region and native `<progress>` element (`"model downloading…"`). When semantic search returns matches, item rows SHALL display a subtle monochrome `"semantic match 0.xx"` chip showing cosine similarity without replacing the 4D signal score.
5. **User Toggle & Server Fallback**: Users SHALL be able to toggle semantic search ON/OFF in `ItemList.tsx` and `CommandPalette.tsx` (persisted in `ReaderSettings.semanticSearchEnabled`). When semantic search is toggled OFF, search SHALL run instant keyword-only matching with zero worker/network embedding calls. When semantic search is ON but WebAssembly/Web Workers are unavailable or the local model has not finished downloading yet, the client SHALL fall back gracefully to `POST /api/embed` when an embedding provider is configured online, or keyword matching otherwise.
6. **Worker Bundle Isolation**: Built Cloudflare Worker artifacts (`dist/worker/`) SHALL NOT bundle `@huggingface/transformers` or ONNX/WASM runtimes and SHALL remain well under the 64 MiB uncompressed limit.
7. **Deterministic Unit Tests**: `tests/semanticSearch.test.ts` SHALL verify cosine similarity, `0.6 * semantic + 0.4 * keyword` hybrid ranking, 4D score preservation, settings sanitization, and fallback ordering using stubbed vectors only (zero model downloads or live network calls).
